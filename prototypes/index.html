WarmPath design directions

Three takes on the same four screens: goal box, path map, people panel, alum reply page. Each differs in style and in how much motion it asks the team to build. All run on the same invented data, shaped like the API contract in docs/mvp.md.

Thermal

The path is warm because people walked it. Each of the 14 alumni who reached the goal is a strand; where strands stack, the route burns brighter. A gold honeycomb sits behind it all, and each cell on the route fills by how many strands cross it. The other 286 alumni drift behind as dust.

Motion
High. A WebGL particle field, routes that draw themselves, a living map.
Built with
React, react-three-fiber, ShaderGradient
Closest to
The Active Theory reference
Open the flowAlum reply page

Transit

The transit map from the vision doc, taken literally. Each activity type is a line, each stop a station sized by its count. Stops you have are ticked off, the next one is the blue station, and the ask is a ticket the alum punches.

Motion
Medium. Lines draw from You outward, riders travel the lines, the next-stop flag slides between stations.
Built with
Plain SVG and the Web Animations API. Maps directly onto React Flow.
Closest to
A buildable hackathon map with one strong moment
Open the flowAlum reply page

Engineering pad

The goal as a homework problem on green engineering paper: Given, Find, Solution. It shows its working, so the lift arithmetic is on the page and the next stop is the boxed answer. Highlighter marks what you have; red pencil marks what is next.

Motion
Low. Press feedback and a few 200ms reveals. Nothing draws itself.
Built with
HTML and CSS, about 150 lines of script
Closest to
A wireframe that already has a point of view
